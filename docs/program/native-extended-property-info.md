SfxExtItemPropertySetInfo is the actual complete XPropertySetInfo component, derived from the original SfxExtItemPropertySetInfo_Base and the genuine WeakImplHelper specialization. Its three declared methods use real Property values and Sequence<Property>; no parallel query provider or host-array metadata facade is registered. SfxItemPropertyMapCompare2 retains original value-name comparison through OUString.lessThan.

Unlike the ordinary map's borrowed schema pointers, the extended component owns copied entry values. Original schema entries are inserted first, extension descriptors next, and the first same-name entry wins. The compiler binding checks for accepted insertion before copying entry members through their actual copy constructor. Reserve syntax has no separate meaning for the JS-backed vector. Constructor failure destroys already constructed native value members. Component final release destroys its cached sequence and value-vector members through the real weak-object destructor dispatch.

Each extension descriptor crosses the original checked sal_Int16 handle conversion before unsigned nWID storage. Negative handles are consequently observable as unsigned handles in returned metadata; WRITER452/CALC-519 record this suspected upstream issue without changing it. Descriptor sequence fields use the existing real generated struct assignment/ownership mechanism. Returned sequences own copied handles sharing the cached storage until COW; returned values remain alive after component destruction. Native counted UTF16 lookup retains embedded NULs, surrogate units and case distinctions.

Six critical cases use genuine native entry values, generated descriptors, UNO sequences, References, XPropertySetInfo/XTypeProvider queries and weak adapters. They cover source ordering/duplicates, independent input lifetime, cached sequence COW, returned sequence lifetime, final strong release, exact name lookup/unknown exceptions and signed-handle boundaries. No dedicated matching test was found in pinned svl/qa or sw/qa/core/unocore after exact class and broader itemprop/property-info searches; existing related native-helper tests accompany these local critical cases.

The older ordinary SfxItemPropertySetInfo host-array projection, Writer static-map provider and consuming model metadata still need migration. This new extended component is not substituted into Writer merely to hide those gaps. Normal property-info/static-schema wiring, SwXTextDefaults, complete DOCX/XLSX import/export and mounted Open/download/Worker acceptance remain incomplete. Physical ABI and unconsumed broad module parity remain unverified. Existing browser file/autosave/recovery policies are unchanged; the approved task and goal continue.
