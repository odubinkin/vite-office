# Native ZIP byte streams

Pinned source: LibreOffice26.8.0.2 commit9bc445578031fecf56086729d8e4940c77e14d65, package/inc/ByteChucker.hxx and ByteGrabber.hxx, package/source/zipapi/ByteChucker.cxx and ByteGrabber.cxx. Reference checkout HEAD and the four clean source paths were verified.

Both original final, non-UNO helpers now have complete declared methods. They own genuine Reference and signed-byte Sequence values and use the existing native XSeekable query machinery. Header paths reexport the single implementation. Destruction is explicit and reverses native member lifetime; it does not flush or close caller streams. Constructor query exceptions unwind the already acquired stream reference, lowering C++ compiler lifetime behavior without altering the propagated error.

ByteChucker retains its2/4/8-byte sequences and their original raw writable pointers. WriteBytes forwards the actual value, integer methods write little-endian signed-byte cells, and GetPosition dereferences the queried seek interface without adding a guard. Calling GetPosition with no seek interface remains outside the initialized native dereference domain; writes can still use a nonseekable genuine output. UInt64 uses BigInt, preserving all64 bits. Retaining a Sequence argument and writing another integer of the same width preserves the original alias mutation (CALC-503/WRITER434).

ByteGrabber retains input and optional seek references, an explicit non-UNO ByteReader crosscast, the original four-byte scratch Sequence and eight uninitialized raw array cells. Integer methods use one raw readSomeBytes call or a UNO readBytes call; partial counts return zero after consuming that prefix (CALC-502/WRITER433). The general raw readBytes method instead calls readSomeBytes on both paths and copies only the returned prefix in the fallback. Changing input keeps original stream-assignment, seek-query and raw-crosscast order. Missing seek operations throw actual empty IOException values.

Tests use actual SequenceInputStream, UNOMemoryStream, OSequenceOutputStream and native Sequence/Reference owners. Complete test-only input/output callers deliberately supply only the declared stream interfaces, with no fake query/provider/package owner. Literal octet tables independently verify integer widths and endian order; integration composes both helpers through the real shared memory cursor. Short-read, input-switch, native exception, retained-buffer and caller-lifetime cases cover critical scenarios. No direct ByteChucker/ByteGrabber QA case was found in pinned package/qa; these are source-derived tests, not a claimed replay of full package services.

Raw lvalue maps lower primitive native pointers/array cells only. Physical pointers, RTTI, allocation failure, ABI, native compiler unwinding and cross-thread scheduling remain unverified. The existing bounded ZIP32 ZipFile/ZipOutputStream transport is not yet the full native ZIP implementation and is not relabeled as such. Complete native package entry/storage/write owners, DOCX/XLSX model/filter import/export and existing Worker/UI acceptance remain unfinished. Browser open/save/autosave/recovery choices remain unchanged.
