# Native memory ZIP catalog reader

Pinned source: LibreOffice26.8.0.2 commit9bc445578031fecf56086729d8e4940c77e14d65, `package/source/zipapi/MemoryByteGrabber.hxx` and `ZipFile.cxx`, `ZipFile::readCEN`.

The complete original final non-UNO MemoryByteGrabber is implemented at the matching source directory. Its Sequence constructor borrows actual const element storage and its pointer/count constructor borrows actual byte storage plus offset. getCurrentPos performs pointer addition, remainingSize subtracts the cursor, and skipBytes keeps original unchecked signed arithmetic. Original deleted-rvalue/lvalue restrictions are compiler contracts not fully expressible by this TypeScript binding; caller lifetime remains required. There is no fabricated Sequence, seek interface, service or pointer-query provider.

Every integer method first checks the complete width. Insufficient bytes return zero without consuming any byte, unlike ByteGrabber's stream short-read path. ReadUInt8 and ReadUInt16 keep the original signed return declarations (CALC-504/WRITER435), while ReadUInt32 and ReadUInt64 preserve their unsigned values. Existing signed logical SAL cells, typed byte storage and BigInt represent these scalar operations; physical C++ signed conversion and ABI are not certified.

The bounded existing ZipFile central catalog now uses this helper in original field order over an actual signed-byte CEN buffer: signature, versions, flags, method, time, CRC, sizes, signed lengths, skipped disk/attribute fields and local offset. It keeps original negative-length checks and advances over names/extra/comment bytes through the helper. The transport catalog's existing unsigned flag/CRC fields are explicitly narrowed at that boundary. Names are copied from the helper's current raw pointer for the existing local-record comparison. Counted UTF8 decoding uses the genuine OUString constructor and original default SAL conversion flags, independently of the ZIP UTF8 bit, exactly as readCEN. The old fatal host decoder and undeclared-UTF8 rejection are removed; tests retain replacement for malformed raw name bytes and actual BMP non-ASCII names without the flag. EOF scanning and local-header verification remain the existing bounded transport, as do ZIP32/resource/host-exception limits; this change does not certify full native ZipFile parity.

Critical tests independently pin literal scalar values, borrowed Sequence changes, raw-pointer offsets, nested borrowed readers, short-read cursor stability, valid backward skips and negative remainders without invalid pointer dereferences. Actual ZIP mutations cover all three signed length fields;32767/32768-byte names pin the source boundary. The old bounds fixture uses a positive0x7fff length so it still checks bounds instead of the earlier negative-length guard. No direct MemoryByteGrabber case was found in pinned package/qa; these are source-derived critical tests, not a full upstream package-service replay.

Full native ZipEntry/ZipOutputStream/package/storage owners, DOCX/XLSX document/model/filter import/export and existing Worker/UI acceptance remain unfinished. Pointer/allocation/ABI/rvalue/thread guarantees are unverified. Browser open/save/autosave/recovery decisions remain unchanged.

The later native ZIP64 catalog checkpoint supersedes the old EOCD scan and ZIP32-only input restriction with original findCentralDirectory/readExtraFields, while retaining resource and flat transport boundaries. See `native-zip64-catalog.md`.
