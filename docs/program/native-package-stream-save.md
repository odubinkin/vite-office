# Native plain package stream save prerequisites

`ZipPackageStream::saveChild` now connects real DATA-mode streams and loaded plain package members to the original synchronous `ZipOutputStream`/`ZipOutputEntry` owners. The manifest uses the original fixed three PropertyValue slots, including an empty Version, and is appended after the write attempt for PACKAGE/OFOPXML formats. ZIP format adds no manifest row. An actual source failure returns false without pretending that the package committed successfully.

The represented branches include seekable STORED size/CRC prepasses, original nonseekable compression optimization, raw transport of existing members with a matching method, changed-compression member input, JPEG handling and small-stream DEFLATE. Successful writes close and release the own input, transition to package-member mode, copy the actual written entry and negate its offset as in the source. The record copy preserves independently owned OUString storage. The output compressor borrows the actual nullable ZipPackageStream pointer; it uses no substitute parent/provider.

Tests operate on actual native UNO/RTL/context/memory/package objects and unchanged upstream archive members. Node zlib independently decompresses emitted data and verifies central-directory CRC/size fields. Source buffer boundaries and the100000-byte synchronous limit are exercised. The actual main/DOM-free Worker probe saves a package factory stream and reopens its bytes through the raw native package reader. This is not a complete document filter or package commit.

WRITER625/CALC692 preserves the source case where disabling compression on a loaded DEFLATED non-JPEG member still produces DEFLATED output. WRITER626/CALC693 preserves a new plain stream's separate Size property snapshot of minus one after a successful write. Supplementary UTF16 filename units remain rejected by the existing original filename validator; supplementary characters in stream contents remain supported.

Pending source profiles remain explicit: DETECT/raw encrypted stream parsing, encrypted output, production scheduling of background entries above100000 bytes, parallel deflation above1000000 bytes, full package commit/reinitialization and XStorage/SfxMedium/filter/UI orchestration. No fallback changes those source branch thresholds or algorithms. The original background entry object/task/temp-file/error-retention work now exists (see `native-zip-background-task.md`); its worker scheduling and complete upstream threaded package QA remain pending. Physical native ABI/allocation/thread scheduling and whole document/UI acceptance remain unqualified. The earlier complete ZipPackage coverage failure remains retained; passing a stream profile does not qualify that owner or erase its missing classic SAX metadata path.
