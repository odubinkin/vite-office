# Native ZIP64 catalog and extra fields

Pinned LibreOffice26.8.0.2 commit9bc445578031fecf56086729d8e4940c77e14d65: `package/source/zipapi/ZipFile.cxx`, `findCentralDirectory`, `readExtraFields`, consumed normal `readCEN`/`readLOC_Impl` checks; `include/comphelper/seqstream.hxx`, `comphelper/source/streaming/seqstream.cxx`; `offapi/com/sun/star/packages/zip/ZipException.idl`.

The existing bounded ZIP transport now uses the original directory search through actual ByteGrabber, MemoryInputStream, native Reference and raw memory-reader owners. MemoryInputStream's const sal_Int8 pointer binding also borrows actual Int8Array/Uint8Array storage, retaining signed byte reads and caller ownership without an archive-sized address provider. Tail/locator/directory buffers lower native primitive stack/vector arrays; only initialized prefixes are read. ZIP64 fields remain BigInt through source signed-width conversion, disk/count/version consumption, size/offset correspondence and checked addition. The current transport converts validated bounded offsets and sizes at its catalog boundary.

Static readExtraFields retains reference lvalues and ordered updates, signed16 counter narrowing, unconditional Zip64 size/compressed/offset reads, optional tail skipping, unknown fields and exact Unicode Path byte comparison. Redundant Unicode-name CRC is ignored as source. Actual generated ZipException values inherit real Exception/OUString/Reference/Type owners; native private mechanism failures are captured as primitive type/message causal diagnostics and destroyed once before throwing the existing public host Error envelope; no destroyed UNO value is retained as cause. That boundary is not a claim that the flat ZipFile is the complete native stream/context/mutex owner.

CEN count-to-length and STORE size consistency checks precede catalog insertion. The existing LOC adapter now validates eagerly during construction, consumes original extra fields, compares decoded counted UTF8 names and lengths, ignores flag bits1/2/11 and only compares nonzero duplicated CRC/size values. Payload inflation and CRC verification stay on real entry reading. Full native descriptor validation, overlapping/hole intervals, FAT/case-insensitive catalog checks, native ZipEntry/ZipOutputStream and parent package/storage owners are still unfinished. Existing64MiB/entry/count/expansion/total-byte transport limits are unchanged; enabling ZIP64 metadata does not admit unbounded documents.

Committed upstream fixtures are unchanged and hashed in `apps/office/src/package/qa/cppunit/data/README.md`. Normal `ZipPackageTest::testTdf163341` now loads the ZIP64 ODS catalog and reads every real payload/CRC; `testUnicodeODT` and `testUnicodeDOCX` reject inconsistent Unicode extras. These translate the normal assertions at the actual current ZIP layer, without inventing a service factory or claiming complete XStorage/ZipPackage service exception parity. Their recovery portions remain outside the intentional application policy and are not simulated. Additional real-record mutations exercise ZIP64 locator/end/extra fields, cross-record counts, signed arithmetic, Unicode matching, typed native input storage and generated exception lifetime.

CALC-505..508 / WRITER436..439 document preserved source conditions: the directory-disk sentinel operand, ignored END comment length, unconditional Zip64 extra assignments and the unchecked under-five Unicode-name view range. No correction is applied to those original operations. Invalid physical pointer/view/allocation/overflow domains, C++ rvalue/ABI/thread guarantees and full package/service behavior are not certified by local tests. Full DOCX/XLSX model/filter import/export and existing Worker/UI acceptance remain unfinished. Existing browser open/save/autosave/recovery choices are unchanged.
