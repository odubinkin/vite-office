# Writer DOCX pipeline

## Status

Implementation is in progress under task `202610251549-V4DQJW`, following the
user-approved shared OOXML → Writer DOCX → Calc XLSX plan. DOCX is not yet
advertised in the application's Open or download controls. Primary browser
storage remains ODT; recovery and autosave product decisions are unchanged.

## Source ownership

The pinned reference is LibreOffice `9bc445578031fecf56086729d8e4940c77e14d65`.
`WriterFilter` owns filter entry and dispatch. Import follows
`OOXMLStreamImpl`/`OOXMLDocumentImpl` into `DomainMapper`, which consumes the
existing `SwXTextDocument`, text, paragraph, style and table interfaces. Export
belongs to `DocxExportFilter`, `DocxExport` and `DocxAttributeOutput` over the
canonical Writer graph. DOCX is not converted to an intermediate ODT document.

The shared prerequisite `R2DJ64` supplies actual ZIP/SAX fragments,
relationships, type metadata and native URI handling. Its implementation commit
is `06a4c723d3b6699f098769caa31df70c99bf4e4b`.

## Native factory generation

Run `python3 scripts/writer-ooxml/generate-factory.py` to regenerate the
consumed `OOXMLFactory_wml.tables.ts` and synchronize the three byte-exact native
token/namespace inputs. Use `--check` to verify without changing those outputs.
The script invokes unchanged pinned `namespaces.py`, `modelpreprocess.py`,
`factoryinc.py`, `resourceids.py` and `generate-tokens.py`, then uses original
`factoryimpl_ns.py` schema collectors. Native temporary outputs stay inside an
owned, automatically removed repository-local coverage directory.

The current data slice contains 24 complex definitions plus their referenced
list definitions: 59 attributes, 231 element mappings, 253 resource mappings,
82 list spellings and 25 action records. Omitted definitions never renumber
admitted IDs. Attribute actions are executed by the namespace factory; the
remaining stream action records are metadata for the pending context pipeline.
The original generated header/implementation contracts share the existing
`OOXMLFactory.ts` owner; generated namespace lookup and constant tables retain
their `OOXMLFactory_wml` owner names. No schema DTO replaces the Writer graph.

Native binary/drawing/service variants are not advertised by this resource
slice. Native undefined floating-to-int casts and null attribute dereferences
are rejected explicitly at the host boundary; no wrap, saturation or successful
native result is claimed for those inputs.

## Native parser state

`OOXMLParserState` retains native shared group flags, context handles and document note/target delegation. Cell/row properties reset to allocated empty sets after delivery; table properties persist across rows. Third-level floating table positioning is filtered from a copy without changing the saved properties. Postponed breaks use `OOXMLBreakHandler` and retain native byte markers and context-property delivery order. Explicit `dispose()` binds the native handler destructor, including exception unwinding.

Textbox nesting intentionally keeps the native single saved state (WRITER127). Host errors expose undefined native null-document dereference and table-stack underflow; every valid table push/pop updates all four stacks together, making the native floating-stack nonempty guard redundant after the checked pop precondition. These protocol owners do not yet establish complete XML document dispatch or application Open support.

## Native fast contexts and SAX dispatch

The stream lazily provisions its own synchronous `FastSaxParser` and registers all 82 unique native URI bindings from the original namespace generator and `factoryimpl.py` ordering. Transitional and strict XML share the original fast-token identities. The existing bounded host XML driver supplies lexical parsing; native context-stack behavior, null-subtree suppression, pending-character aggregation and native first-failure SAX wrapping are preserved around it. Namespace URI normalization beyond the represented exact OOXML URI spellings is not yet implemented.

`OOXMLFastDocumentHandler` initializes the root state once, delegates note identity and marks substreams as already in a section. `OOXMLFastContextHandler`, Stream, Properties and Value owners dispatch native schema actions and ordered property/value handoff. Unknown XML children use the original defaulted base-copy semantics (without incrementing context count); known tokens outside a grammar return null. Native xml:space inheritance, XML-only whitespace trimming, MCE state, footnote-marker consumption, deferred breaks and paragraph CR/group ordering are retained. The redundant negative section guard after the native nonvirtual section-close path is omitted by its clearing invariant; no instrumentation exclusions or private-state mutation are used.

Tests exercise actual fast SAX through the generated factory for strict/transitional text documents and inspect run formatting on a real `SwDoc` reached through `DomainMapper`. Whole-document section/style/list/table application is still pending. Encountering a not-yet-ported definition, resource class or cross-namespace factory fails explicitly at the incomplete implementation boundary; it does not silently pretend that the full DOCX import succeeded. This boundary is not a claimed native semantic replacement and must disappear as the missing owners are implemented before application acceptance. DOCX export and the existing application UI routes remain pending.

Native callback failures retain only the first saved cause and continue the current16KiB UTF8 input block before failing at its checkpoint, as `Entity::saveException` and `FastSaxParserImpl::parse` do. The current host exception carrier exposes SAXParseException field names and the original saved reference; it does not claim a generated/registered UNO exception or Any value. Locator and lexical diagnostics come from the host XML engine. Native-generated SAX exception typing/ABI remains unverified.

## Page-frame prerequisite

`SwPageDesc` owns four real document-pool `SwFrameFormat` instances. Native usage
flags, registered-name uniqueness, independent format names and copy/follow
semantics replace the previous geometry-only state. Existing browser geometry
values are projections of these owners. Native `SwTextGridItem` owns all eleven
fields, typed UNO members and original paper-mode arithmetic. Page-style grid
properties and `PageStyleLayout` use the original item and enum contracts.

Registered pool defaults now have actual `ItemInfoStatic`/`ItemInfoUser` metadata,
so user defaults follow the existing pool state machine without a synthetic
contiguous Which range. Browser graph/Worker/storage records retain all four
direct page item sets, their names, usage flags and optional user grid defaults.
Legacy geometry-only records remain accepted. Frame-size encoding is shared
with tables; complete LR transport preserves relative measures, proportions,
gutters and flags. The browser codec copies original raw `propLeft`/`propRight`
scalars explicitly because public proportional setters rescale stored values.
This is a host serialization binding, not an alternative native item contract.

Section application, document default-page-mode notifications and complete style
loading remain pending. ODT currently preserves represented page geometry but
does not yet serialize the new grid fields. This checkpoint does not establish
DOCX import/export, application file routing or complete native parity.

## Native identity correction

The pinned `hintids.hxx` has additional text and paragraph attributes compared
with the old numeric browser table. The consumed paragraph identities were two
positions behind upstream, and identities from `RES_PARATR_LIST_BEGIN` onward
were three behind. Current core constants and native row/cell ranges now use
the pinned values; `RES_FRM_SIZE` is 93 and `RES_TEXTGRID` is 125. The old pool
also registered `SvxProtectItem` under 127 (the old frame-direction slot),
instead of the actual `RES_PROTECT` identity 110. That registration is corrected.

Browser graph version17 writes native identities exclusively. Its explicit v16
ingress migrates old identities and the protection misregistration before
restoring concrete native items. Item values, physical dimensions and other
numeric fields are unchanged. Core APIs do not accept legacy aliases.
`npm run check:writer-hintids` resolves the actual pinned C++ expressions and
checks every consumed numeric declaration; the main verification pipeline
includes this check. Earlier numerical claims in historical checkpoint notes
describe the former incorrect local table and do not establish native parity.

The older extracted-native test recordings use their original numeric attribute
labels as a test protocol. Their operations and expected results remain
unchanged. A test-only binding maps those seven paragraph/list labels to real
current native identities and projects result labels back for comparison. This
binding is absent from the core and from document transport. The independent
pinned-expression guard proves numeric identity; recorded native probes prove
the represented behavioral sequences. Native pooled-default flags are asserted
through pool ownership tests, while value comparisons use the items' native
`equals` contracts rather than comparing allocation/default bookkeeping fields.
