# Native package and own-stream state prerequisites

`ZipPackage` now owns its original default package format, actual shared OSL mutex and root folder, and creates actual `ZipPackageFolder`/`ZipPackageStream` objects. The first argument alone controls folder creation through the original boolean extraction and false fallback. No package service or replacement storage factory is registered by this checkpoint.

`ZipPackageStream` retains represented native constructor defaults, ZIP-entry copying, package-member state transitions, input replacement, explicit data-stream mode, lazy seekability and independent `WrapStreamForShare` cursors over its real source. `MediaType`, `Size` and `Compressed` preserve source type extraction, exception argument2, value lifetime and compression-selection order. In particular, an explicit false compression flag does not prevent a later text/ole media type from enabling compression; the source order is retained (WRITER623/CALC690). `Size` starts at zero even while the entry's unknown ZIP sizes are minus one.

All callers use actual package/context/stream owners. Tests use native `Any`, `Sequence`, UNO queries, the original shared mutex and memory stream. Chromium main and DOM-free Worker exercise creation and independently positioned readers. These checks do not qualify physical native allocator/ABI/multithread/destructor interleavings.

Raw ZIP stream initialization now builds the original folder/member tree through actual ZipFile and reads plain members through native input streams. Original hierarchical lookup/cache paths, recursive extension media assignment and non-recovery ZIP checks are represented. Original package QA malformed fixtures exercise the actual stream argument overload; unchanged Writer/Calc archive members are compared against independent Python zipfile lengths and SHA256 values. Main/Worker reopen production storage bytes through this raw ZIP owner. WRITER624/CALC691 records the preserved trailing-slash cache-parent selection.

The OFOPXML metadata orchestration has been transferred but its positive path is unqualified: it still requires the missing real classic SAX Parser, rather than a substituted FastParser service. Whole-owner coverage remains below the required90 gate; this checkpoint is work in progress.

Remaining work includes ODF manifest/native OFOPXML metadata initialization, complete package interface/type list, metadata/manifest orchestration on that owner, imported encryption state, raw/encrypted APIs, raw/encrypted/threaded stream-save profiles, package commit and XStorage/SfxMedium integration. Plain DATA-mode/small synchronous stream saving and raw member transport now use the original actual ZIP output owners; remaining encrypted/raw-detection/threaded boundaries are explicit (see `native-package-stream-save.md`). The encryption interface is not advertised; encryption property paths are explicitly unavailable. These errors are development gaps, not claims of native exception parity or completed document behavior.

The four pre-existing metadata/medium type errors and two module-boundary diagnostics remain. Complete DOCX/XLSX import/export/reopen and mounted UI acceptance remain required. No source default, native crypto algorithm or browser open/save/autosave/recovery flow is changed by this prerequisite checkpoint.
